# CardGame DI V2 实施计划

> **执行要求：** 使用 `subagent-driven-development` 或 `executing-plans` 逐任务执行；行为变更必须先走 TDD，完成声明前使用 `verification-before-completion`。

**目标：** 在 CardGame 中以严格、可维护的纯 C# DI V2 和 Unity 主线程注入适配器，完全替换旧 `DIContainer`。
**架构：** `ContainerBuilder` 生成不可变模型，`ServiceContainer` 与层级 `ServiceScope` 负责解析和所有权；`RazorFramework.DI` 不引用 Unity；`RazorFramework.Unity.DI` 只处理 Unity 对象成员注入。
**技术栈：** Unity `6000.3.10f1`、C# 9、Unity Test Framework `1.6.0` / NUnit、Node.js Harness、Unity asmdef。
**基线：** `01ade590338cd683785fb3604d9fb22270b6c266`。

## 全局约束

- 只服务 CardGame，不保证旧 `DIContainer` API 兼容；
- 可维护性与正确性优先，不为减少改动保留已知风险；
- Core 命名空间为 `RazorFramework.DI`，禁止编译期 Unity 引用；
- Unity 相关代码只在 `RazorFramework.Unity.DI`；
- 一次只推进 `feature_list.json` 中一个 `in-progress` 功能；
- 不迁移 `Boot`、`Events`、`Input`、`Lifecycle`、`MVVM`，不实现 feat-003；
- 每项行为先写独立失败测试并确认 RED，再写最小实现；
- Unity 生成的 `.meta` 必须提交，`Library/`、`Temp/`、`Logs/`、`UserSettings/`、`.sln`、`.csproj` 不提交；
- 每个任务提交前运行相关测试，最终必须运行 Node、portable、full 和范围化 whitespace 检查；
- IL2CPP、linker stripping、AOT 与目标平台构建未纳入完成宣称。

## Task 1：建立不可变注册模型与构建期验证

**文件：** 创建 Core asmdef、抽象、注册、激活计划、异常、builder、依赖图验证器、容器骨架和 `BuilderValidationTests.cs`。

**RED：**

- 重复默认注册必须失败；
- 缺失构造依赖必须给出 `MissingDependency` 和路径；
- 间接依赖环必须给出闭合路径；
- 多 public 构造函数只能通过唯一 `[InjectConstructor]` 消歧；
- 成功 `Build()` 后 builder 冻结，失败 `Build()` 不消费 builder。

运行：

```powershell
$env:UNITY_EDITOR='C:\Program Files\Unity\Hub\Editor\6000.3.10f1\Editor\Unity.exe'
node scripts/harness/verify.mjs --full
```

**GREEN 实现：**

- 固定 `RazorFramework.DI.asmdef`：`rootNamespace`、空 `references`、`autoReferenced: true`、`noEngineReferences: true`；
- 复制源注册生成 `ContainerBuildModel`；
- 用 DFS 验证缺失依赖和循环；
- 只接受闭合具体实现和合规 public 构造函数；
- `DependencyInjectionException` 保存稳定错误码和只读路径。

**验收：** Builder 测试通过，Core 编译不需要 Unity 类型。

**提交：** `de6b357 feat: add validated immutable DI builder`

## Task 2：实现 Singleton 与 Transient 解析

**文件：** 修改 `ServiceContainer.cs`、`ServiceRegistration.cs`，创建 `LifetimeOwner.cs` 和 `ResolutionLifetimeTests.cs`。

**RED：**

- Singleton 在根容器内共享；
- Transient 每次解析新建；
- 外部实例原样返回；
- 未注册服务结构化失败；
- `TryResolve` 只对未注册返回 `false`，不得吞构造异常。

**GREEN 实现：**

- `Resolve(Type)`、`Resolve<T>()`、`TryResolve` 按精确服务键工作；
- Singleton 使用线程安全 `Lazy<object>`；
- 构造异常转换为 `ActivationFailed` 并保留真实 inner exception；
- 外部实例不加入容器所有权。

**验收命令：**

```powershell
node scripts/harness/verify.mjs --full
```

**提交：** `bd992e8 feat: resolve immutable DI lifetimes`

## Task 3：实现层级作用域与生命周期图

**文件：** 创建 `ServiceScope.cs`、`HierarchicalScopeTests.cs`，修改容器、验证器、激活计划和所有权代码。

**RED：**

- 两个 Encounter scope 共享同一 Run 服务但不共享 Encounter 服务；
- 根、父、子 scope 只能按定义的直接父子关系创建；
- Singleton 间接依赖 Scoped 必须失败；
- 父 Scoped 依赖后代 Scoped 必须失败；
- 同一服务要求兄弟 scope 必须失败；
- 没有活动 scope 的运行时解析必须给出 `ScopeMismatch`。

**GREEN 实现：**

- `DefineScope<T>()` 和 `DefineScope<T, TParent>()` 建立树；
- `ServiceContainer.CreateScope<T>()` 与 `ServiceScope.CreateScope<T>()` 校验直接父级；
- Scoped 缓存锚定声明 scope；
- 构建期传播最严格的作用域要求；
- 后续终审修订使传播同时携带依赖链，覆盖间接 captive、兄弟冲突、集合冲突与 runtime mismatch。

**精确路径例：**

```text
SingletonNeedsTransient -> TransientNeedsRun -> RunState
NeedsBattleAndShop -> BattleState -> ShopState
```

**验收命令：**

```powershell
node scripts/harness/verify.mjs --full
```

**提交：** `61766b8 feat: add hierarchical DI scopes`，终审路径增强在最终修复提交中完成。

## Task 4：明确所有权、并发与确定性释放

**文件：** 修改 `LifetimeOwner.cs`、`ServiceContainer.cs`、`ServiceScope.cs`，创建 `OwnershipAndConcurrencyTests.cs`。

**RED：**

- 同一 owner 内并发解析 Singleton/Scoped 只构造一次；
- scope 先释放依赖者，再释放依赖；
- 子 scope 先于父 scope；
- 外部 disposable 不由容器释放；
- 一个释放异常不阻断其他实例，最终聚合错误；
- 已释放容器或 scope 拒绝解析。

**GREEN 实现：**

- 每个 owner 维护线程安全惰性缓存和按创建顺序的 disposable 列表；
- Transient 归发起解析的 root 或 scope；
- 释放逆序执行并用 `AggregateException` 汇总；
- 所有生命周期 API 幂等且有 disposed guard。

**验收命令：**

```powershell
node scripts/harness/verify.mjs --full
```

**提交：** `d2d5aed feat: enforce DI ownership and disposal`

## Task 5：集合解析与诊断通道

**文件：** 修改抽象、builder、验证器、容器、诊断，创建 `CollectionAndDiagnosticsTests.cs`。

**RED：**

- 默认注册与集合注册相互独立；
- `ResolveAll<T>()` 按显式注册顺序返回；
- 缺失集合注入空只读列表；
- 集合条目参与生命周期校验与所有权；
- 诊断 sink 抛错不改变解析或释放结果；
- 一次解析失败只产生一次顶层失败诊断。

**GREEN 实现：**

- 新增三种集合注册入口；
- `IReadOnlyList<T>` 构造依赖映射至显式集合；
- `IDiDiagnosticSink` 观察构建、scope、实例、失败和释放；
- `DiagnosticDispatcher` 隔离 sink 异常。

**提交：** `ab0eada feat: add DI collections and diagnostics`

## Task 6：实现 fail-closed 的 Unity 主线程注入适配器

**文件：** 创建 Unity adapter asmdef、属性、异常、主线程守卫、注入器、friend assembly 声明与 UnityDI tests。

**RED：**

- 必需字段和可选属性按基类到派生类顺序注入；
- 正确线程上的 `null` 和 destroyed object 为 no-op；
- 主线程创建、工作线程调用时，在 Unity null 访问前拒绝；
- 工作线程构造并在同一工作线程使用仍必须拒绝；
- 非法字段/属性形状、缺失依赖和赋值错误具有结构化上下文。

**GREEN 实现：**

- `UnityMainThread` 在 `SubsystemRegistration` 清空旧状态，在 `BeforeSceneLoad` 捕获 Unity 主线程；
- 注入器构造和 `Inject` 都调用同一可信守卫；未初始化或错误线程统一 `WrongThread`；
- 测试初始化钩子仅为 `internal`，只对 `RazorFramework.Unity.DI.Tests` 可见；
- 线程检查先于 `target == null`；
- 反射计划按类型缓存，字段/属性规则显式验证；
- `[Inject]` 必需、`[InjectOptional]` 可选。

**限制：** 不提供线程调度；IL2CPP、linker stripping、AOT 与目标平台未验证。

**验收命令：**

```powershell
$env:UNITY_EDITOR='C:\Program Files\Unity\Hub\Editor\6000.3.10f1\Editor\Unity.exe'
```

## Task 7：让 Harness 强制唯一 DI 与纯 C# 边界

**文件：** 修改 `scripts/harness/verify.mjs`、`scripts/harness/tests/verify-entrypoint.test.mjs`，删除旧 `DI/DIContainer.cs`。

**RED fixtures：**

- direct、global、alias Unity import；
- `UnityEngine.Object`、`UnityEngine . Object`、`global :: UnityEngine . Object`；
- 点号附近的块注释与空白；
- 普通、verbatim 和 raw 插值表达式中的 Unity 限定名；
- 普通注释和字符串不得误报；
- 外来 namespace 与单文件混合 namespace；
- 根 `DI/LegacyContainer.cs` 与 `DI/Nested/AlternativeContainer.cs`；
- asmdef 的 `rootNamespace`、`autoReferenced`、`noEngineReferences`、`references` 漂移；
- 规格/计划出现连续大量 `?` 或 replacement character，正常中文问号不误报。

**GREEN 实现：**

- 文本扫描先屏蔽注释、字符和普通字符串，再检查实际 token trivia；插值表达式独立提取；
- 不声称使用完整 C# parser，只覆盖仓库公开契约并以 fixture 固定；
- 根 `DI/` 递归拒绝任意 `.cs`，目录不存在或无 C# 文件时通过；
- 校验 DI asmdef 全部固定字段；
- 对两份中文设计工件执行损坏门禁和最低中文内容检查；
- 删除旧实现，使 V2 成为唯一运行时 DI 源。
